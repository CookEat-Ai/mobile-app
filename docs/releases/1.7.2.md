# CookEat 1.7.2

The demonstration planning flow asks for choices without preselection, uses cuisine photographs, removes the redundant week-review action, and dims days excluded from generation. Recipe browsing caches repeated reads and supports localized search. Planning covers seven consecutive days from the next meal in the user's timezone; current plans can be deleted by their owner. Meal and pantry flows include the pending loading, organization and upload fixes. French copy has been made more natural; equivalent interface changes are localized in all six app languages.

Paired production API: 1.9.8, commit `4f66f848f23f9f48eb2ec1c53127ff333b123f51`, upstream `CookEat-Ai/api`, branch `release/light-meals-1.9.3`. The published cuisine corrections from API 1.9.7 remain in place. Deploy the paired API before shipping this app.

Production: `@gokugen/cookeat`, bundle/package `com.gokugen.cookeat`, API `https://cookeat.info/api`, EAS production environment/channel, fingerprint runtime policy. Expected next builds: iOS 22; Android 9 (live Play maximum is 8). Native AppsFlyer Android package registration requires new binaries.

Preflight: Yarn frozen installation, TypeScript, lint (zero errors; 55 pre-existing warnings), all 36 mobile regression scripts, iOS and Android production Metro exports, Expo Doctor 21/21 and diff checks. Test fixtures use the compatible sibling API to check clock and planning parity. Paywall and purchase code are unchanged from 1.7.1. Reviewer access uses a server-verified revocable product licence; protected Store fields contain its instructions, never source control.

Store state and artifact IDs are recorded separately after upload and review submission. A successful build/upload does not establish storefront publication. Apple release mode is MANUAL.
